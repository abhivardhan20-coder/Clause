# Clause

A jurisdiction-neutral legal document workspace built with React, TypeScript, Vinext, and Cloudflare Workers. It prioritizes plain language, original source wording, and preparation for a qualified lawyer.

## What works without credentials

- Fictional freelance agreement with six source-linked explanations and three points of attention.
- Prepared, clearly labeled sample Q&A, including unsupported-question fallbacks.
- Import UTF-8 `.txt` / `.md` files or paste up to 60,000 characters. Imported documents are explicitly unreviewed until live analysis is available.
- Bounded line comparison with exact additions, removals, and unchanged text. This does not evaluate legal effect.
- Preparation checklist, personal questions, and a downloadable plain-text brief containing the original document.
- Responsive interface, keyboard-operated dialogs and tabs, optional WebMCP tools.

Documents, notes, and questions are kept in browser memory, not persisted. Export before refreshing. The fictional demo uses prepared content; it does not pretend to call a model.

## Run locally

Requires Node 22.13 or later and npm.

```sh
npm ci
npm run dev
```

The preview is served at `http://localhost:5173`. The starter's Cloudflare integration runs the server routes locally.

## Connect live AI

Set server-only `OPENAI_API_KEY` and optionally `OPENAI_MODEL` (default `gpt-4.1-mini`). For local Cloudflare development, copy `.env.example` to `.dev.vars` and fill it in; restart the development server. Never commit credentials. For Sites production, configure these as runtime secrets through Sites and redeploy. The OpenAI Developers plugin can provision an API key securely.

`GET /api/legal` reports only availability, never the credential. `POST /api/legal` supports `review` and `question` actions. The frontend shows the AI option only when a key is configured; users explicitly consent before sending imported text for analysis. Subsequent document questions use the same provider.

The server uses the [OpenAI Responses API with structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs), `store: false`, schema validation, source-ID validation, a 60-second timeout, request-size limits, same-origin checks, and best-effort per-isolate throttling. Original quotations are taken from supplied text, never regenerated by the model. Document text is treated as untrusted input. There is no logging of documents or API credentials in application code.

The application has no document database and makes no retention promises about the upstream AI provider. `store: false` is not a guarantee of zero provider retention. A production rollout beyond the private prototype should add distributed throttling and evaluate model accuracy on representative agreements. The in-memory limiter is not a distributed quota.

## Boundaries

- No PDF/DOCX extraction or OCR: copy document text, or export it as UTF-8 text.
- No legal research, jurisdiction-specific determinations, or advice on whether to sign.
- Source links establish provenance of wording, not factual correctness of an interpretation.
- Long text is split into excerpts. AI may explain up to 12 selected excerpts; the rest remain readable without an explanation.
- Comparison supports 500 lines per version and reports text changes only.
- The app ships in sample mode unless a provider key is configured. The live-provider path requires an integration check with a valid key before relying on it.

## Checks

```sh
npx tsc --noEmit
node --experimental-strip-types --test tests/documents.test.mjs
npm run build
```

Small focused tests cover source preservation, comparison correctness, import constraints, sample-answer scope, and export content. Browser checks cover navigation, citations, document import, comparison, checklist state, responsive layout, and optional WebMCP operations.

## Code map

- `components/clause/workspace.tsx`: document state and navigation
- `components/clause/document-dialog.tsx`: local import and analysis consent
- `components/clause/assistant.tsx`: sample and live question flows
- `components/clause/compare.tsx`: local version comparison
- `lib/documents.ts`: bounded parsing, comparison, export, and request helpers
- `lib/sample.ts`: fictional source and explicitly prepared explanations
- `app/api/legal/route.ts`: validated server-only AI gateway

Keep the Sites hosting metadata and build integration when deploying to Sites.
